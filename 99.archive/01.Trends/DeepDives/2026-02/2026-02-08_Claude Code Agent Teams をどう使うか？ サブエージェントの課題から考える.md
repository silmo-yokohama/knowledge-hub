# Claude Code Agent Teams をどう使うか？ サブエージェントの課題から考える

## 記事の要約

- Claude Code v2.1.32で追加されたAgent Teamsを、従来のサブエージェントとの比較から使い分けを整理
- サブエージェントは「結果だけ返す作業者」、Agent Teamsは「議論しながら協調するメンバー」という明確な対比
- サブエージェント利用時の3つの課題（不透明性・割り込み不可・オーケストレーション限界）をAgent Teamsが解決
- ブレインストーミング、API設計の協調、記事執筆、ナレッジベース整備など具体的ユースケースを提示
- OSSエコシステムへの影響として、公式機能の高速進化がサードパーティツールの陳腐化を早める問題を指摘

---

## 詳細の深掘り

### サブエージェントの3つの課題

記事はまず、従来のサブエージェント方式の問題点を3つに整理する。

**課題1: 不透明性** — サブエージェントは途中経過が追えず、「正しく進んでいるのか」を確認できない。最終結果が返ってくるまでブラックボックスになる。Agent Teamsではキーボード操作でチームメイトの作業をリアルタイムに確認できるため、この問題が解消される。

**課題2: 割り込み不可** — サブエージェント実行中に方針転換の指示を出すことができない。Agent Teamsなら `SendMessage` ツールで「ここのトーンを変えて」といった直接メッセージが可能。

**課題3: オーケストレーション限界** — 複数の役割を連携させる使い方に不向き。例えば「PM視点」と「エンジニア視点」を並行処理して突き合わせるような高度なワークフローを実現できない。

### サブエージェントとAgent Teamsの比較

| 項目 | サブエージェント | Agent Teams |
|------|-----------------|------------|
| コンテキスト | 独自ウィンドウ、結果をメインに返す | 完全に独立 |
| 通信方式 | メインエージェントのみに報告 | チームメイト同士の直接メッセージング |
| 調整方式 | メインが全作業を管理 | 共有タスクリストで自律的に調整 |
| 向いている場面 | 結果が重要な集中タスク | 議論・協調が必要な複雑作業 |
| トークンコスト | 低い（要約される） | 高い（各メンバーが独立） |

重要なのは、Agent TeamsがサブエージェントのComplete Replacementではないという点だ。単純なタスク分割にはサブエージェント、議論や協調が必要な場面にはAgent Teamsと使い分けるのが最適。

### 具体的なユースケース

記事では4つの具体的な活用シーンを紹介している。

**1. 上流工程でのブレインストーミング** — PM、アーキテクト、Devil's Advocate、セキュリティレビュワーなど複数役割をチームメイトに担わせ、議論の結果をDesign Docにまとめる。テキストベースのためファイル競合リスクが低い。

**2. API設計のフロント/バック協調** — バックエンドとフロントエンドがSwagger/OpenAPI仕様で直接対話し、齟齬を解消してから並行実装に移行する。

**3. 記事執筆ワークフロー** — 著者がリードとなり、リサーチャー・ライター・ファクトチェッカーに直接フィードバックする構成。

**4. ナレッジベースの並行整備** — 複数ドメイン領域を1セッション内で並行整備しつつ、リードが全社統一のトーンやルールを保つ構成。

## キーポイント

- サブエージェントとAgent Teamsは「代替」ではなく「使い分け」の関係
- Agent Teamsの最大の価値は「途中介入」と「メンバー間の直接対話」
- OSSの「公式機能に追い抜かれる」ジレンマは、エコシステム全体の課題

## あなたへの関連性

### 実務への応用

フリーランスとしてAPI設計を含むフルスタック案件を手がける際、「フロントエンド視点のAgent」と「バックエンド視点のAgent」を協調させてSwagger定義を先に固める、という手法は即座に実践可能。特にNext.js + バックエンドAPI（Go/Python）の案件で、両サイドの整合性を開発初期に担保できるメリットは大きい。

また、knowledge-hubプロジェクトのスキル開発でも、スキル設計者とテスター役のAgentを組ませることで品質を高められる可能性がある。

### 学習ヒント

この記事はClaude Codeの使い方だけでなく、「上流工程」「アーキテクチャ設計」「API設計」といったPROFILE.mdの学習領域（アーキテクチャ設計、クリーンアーキテクチャ、DDD）に直結する内容。特にAPI設計のフロント/バック協調のユースケースは、バックエンド開発を学ぶ足がかりとしても有用だ。
