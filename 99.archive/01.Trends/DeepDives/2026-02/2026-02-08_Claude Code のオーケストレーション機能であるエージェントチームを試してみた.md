## 記事の要約

- Claude Code v2.1.32で追加された「エージェントチーム」機能は、複数のClaude Codeインスタンスがチームとして協調動作する仕組み
- 従来のサブエージェントとの最大の違いは、メンバー同士がリーダーを介さず直接コミュニケーションを取れること
- 環境変数 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` で有効化。表示モードはin-processとSplit Pane（tmux/iTerm2）の2種類
- タスク管理システムとファイルロック機構により、複数エージェントの並列作業と競合防止を実現
- トークン消費が多いため、用途に応じた使い分けが重要

---

## 詳細の深掘り

### エージェントチームの基本構成

エージェントチームは「チームリーダー＋複数メンバー」という階層構造をとる。1つのセッションがチームリーダーとして機能し、他のセッションにタスクを割り当てて作業を調整する。チーム設定は `~/.claude/teams/{team-name}/config.json` に保存され、`leadAgentId` プロパティでリーダーが指定される。`members` 配列で各メンバーの役割が定義される仕組みだ。

タスクは `~/.claude/tasks/{team-name}` に保存され、依存関係を持つタスクは完了順に自動実行される。各メンバーは独立したコンテキストウィンドウで動作するため、お互いの作業を邪魔することなく並列処理が可能になる。

### 有効化方法と表示モード

2026年2月時点ではResearch Previewの実験的機能。`~/.claude/settings.json` に以下を追加して有効化する：

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

表示モードは2種類ある。**in-processモード**は1つのターミナルで全メンバーが動作する。**Split Paneモード**はtmuxまたはiTerm2を利用して各メンバーが分割ペインで動作し、リアルタイムに各メンバーの進捗を視覚的に確認できる。

### 運用上の注意点

複数エージェントから同時に承認要求が来ると、ユーザーがボトルネックになる。権限設定をあらかじめ見直し、承認なしで実行可能なコマンドを定義しておくことが推奨される。また、ファイル競合を避けるために担当範囲を明確に分離し、チームメンバー1人あたり5〜6個のタスク割り当てが効率的とされている。

プロジェクト固有の情報は `CLAUDE.md` で共有する必要がある。各メンバーが独立したコンテキストで動作するため、共有すべき情報が明示的に記述されていないと、メンバー間で認識のズレが生じる可能性がある。

## キーポイント

- エージェントチームの核心は「メンバー間の直接通信」。サブエージェントの「結果を返すだけ」とは根本的に異なる
- Research Preview段階のため破壊的変更の可能性あり。プロダクション利用は慎重に
- トークン消費はメンバー数に比例して増大。コスト意識を持った運用設計が必須

## あなたへの関連性

### 実務への応用

日常的にClaude Codeを使うフリーランスフロントエンドエンジニアとして、エージェントチームは大規模タスクの効率化に直結する。例えば、フロントエンド実装とバックエンドAPI設計を並行して進めたり、コードレビューとテスト作成を同時に行うワークフローが構築できる。ただし、1人で使う場合はサブエージェントで十分なケースも多いため、チーム機能が真に必要な場面を見極めることが重要。

現在のknowledge-hubプロジェクトのように、複数のスキルが連携するワークフローでは、各スキルの実行をチームメンバーに委譲するアーキテクチャも考えられる。

### 学習ヒント

PROFILE.mdの「AI/LLM」は深掘りしたい分野の筆頭。エージェントチームはClaude Codeの最新機能であり、いち早くキャッチアップすることで、クライアントへの提案やブログ記事のネタとしても活用できる。Split Paneモードの利用にはtmuxの知識が必要で、DevOps（まだ詳しくない分野）の学習にもつながる。
