## 記事の要約

- Vercelが先週からビルドマシンのデフォルトを「Turbo」（$0.13/分）に変更しており、通常のマシンより1000%高額
- 投稿者はNext.jsアプリのProプランで初回の週次請求が$20相当のビルド分になったことに驚いた
- 最も高価なオプションをデフォルトに設定するのはダークパターンだと批判
- GitHub Actionsへの移行を検討するという声が多数

## 詳細の深掘り

### Turboビルドマシンのデフォルト化問題

Vercelが先週からビルドマシンのデフォルト設定を「Turbo」に変更した。Turboマシンは通常のビルドマシンに比べて1000%（10倍）高額の$0.13/分。投稿者はProプラン加入直後の初回請求で$20相当のビルド分が発生しており、「10年の開発経験で最も高価なマシンがデフォルトになっているのを見たことがない」と述べている。多くのユーザーが設定を確認しないまま高額な請求を受けている可能性がある。

### 代替手段としてのGitHub Actions

コミュニティではGitHub Actionsへの移行を推奨する声が多い。GitHub Actionsは無料枠だけで小〜中規模プロジェクトをカバーでき、Vercelと比較して圧倒的に安価。SSRを使わない静的サイトであればVercelを使う理由自体がないという意見もあり、SSRやISRを使う場合でも他のホスティングプロバイダーで問題なく動作するとの報告がある。

### Vercelの価格戦略への懸念

普段はVercelの価格変更はユーザーにとって有利な方向（画像最適化の改善、Fluid Compute等）だったが、今回のTurboデフォルト化は「搾取的（predatory）」と感じるユーザーが多い。無料プランは優れているが、Proプランに移行した途端、あらゆる設定が最大限の課金を引き出すよう設計されているという不信感が広がっている。

## キーポイント

- Vercelのビルドマシンデフォルトが高価なTurbo（$0.13/分）に変更された — 設定を確認すべき
- GitHub Actionsは費用対効果の高い代替手段として有効
- Vercelの無料プランは依然として優秀だが、Proプランの請求には注意が必要
- SSR不要なプロジェクトでは、そもそもVercel以外の選択肢を検討する価値がある

## あなたへの関連性

### 実務への応用

Next.jsプロジェクトでVercelを利用する機会があるフリーランスとして、直接的に影響する話題:

- **クライアントプロジェクトのコスト管理**: Vercelでホスティングしているプロジェクトがあれば、ビルドマシンの設定を即座に確認すべき。Turboがデフォルトになっていないか要チェック
- **ホスティング選定の判断材料**: 新規プロジェクトの提案時、Vercel vs GitHub Actions + 他のホスティング（Cloudflare Pages等）のコスト比較を提示できる
- **予算が限られた個人開発**: 個人開発ではVercelの無料プランを活用しつつ、ビルドはGitHub Actionsに切り替えることで費用を抑えられる

### 学習ヒント

- GitHub ActionsでのNext.jsビルド・デプロイの構築は、DevOps/CI/CDの実践的な学習になる
- Vercelの代替としてCloudflare PagesやFly.ioなども選択肢に入れておくと、インフラ知識が広がる
