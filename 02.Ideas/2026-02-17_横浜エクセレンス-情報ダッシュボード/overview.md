# 横浜エクセレンス 情報ダッシュボード

> カテゴリ: 趣味・プライベート
> 作成日: 2026-02-17
> ステータス: アイデア段階
> 前回企画: `02.Ideas/2026-02-08_横浜エクセレンス-ファンサイト/`（練り直し）

---

## 概要

横浜エクセレンス（B.LEAGUE）に特化した情報ダッシュボード兼データベース。B.LEAGUE公式サイト（メイン）とスポナビ（サブ）からスタッツデータを自動収集し、試合結果・選手スタッツ・チーム成績を一箇所に集約する。「5クリックかかる情報を1クリックで」をコンセプトに、グラフを多用したスタイリッシュなダッシュボードUIで、スポナビやB.LEAGUE公式では得られないワンストップの情報体験を提供する。試合中はリアルタイム更新に対応し、試合後にはダイジェスト動画の埋め込みやAI生成の試合寸評も表示する。

---

## 5W1H

### What（何を）

横浜エクセレンスの全スタッツデータを集約・蓄積し、グラフやチャートで見やすく表示するWebダッシュボード。試合結果、ボックススコア、選手スタッツ（基本 + アドバンスド）、チーム成績、順位表を網羅。加えてGoogle News RSS・公式HPニュース・YouTubeダイジェスト動画によるマルチメディアコンテンツもトップページや試合詳細に配置する。試合中はリアルタイム更新、試合後にはAI寸評を提供する。

### Why（なぜ）

- スポナビでは TOP → BLEAGUE → B2 → 今日の試合 → エクセレンス と5段階の導線が必要
- B.LEAGUE公式も同様に階層が深く、選手個人の前試合スタッツを見るには何度も戻る必要がある
- 既存のスタッツサイト（bleague-stats.com、B.League Analytics等）はリーグ全体を対象としており、特定チームに特化したダッシュボードが存在しない
- B2リーグのカバレッジは特に薄い

### Who（誰が）

- メインユーザー: 自分自身（Dogfooding）
- 想定ユーザー: 横浜エクセレンスの既存ファン、B2リーグに興味があるバスケファン

### When（いつ）

- 未定（B.LEAGUEシーズン中のリリースが理想）

### Where（どこで）

- Webサイト（レスポンシブ対応、PC/スマホ両対応）

### How（どうやって）

- データ取得: B.LEAGUE公式サイトをメインソース、スポナビをサブソースとしてPythonバッチ処理で自動収集
- ニュース: Google News RSS（「横浜エクセレンス」キーワード検索）+ 公式HP RSS（`yokohama-ex.jp/RSS.rdf`）
- 動画: YouTube公式チャンネルRSS（ダイジェスト動画をゲーム詳細に自動埋め込み）
- リアルタイム: 試合中は30秒間隔の自動更新 + 手動更新ボタン
- AI寸評: 試合データをもとにAIが試合の要約・寸評を自動生成
- フロントエンド: Next.js（メインスキルを活かす）
- データ可視化: Recharts（グラフ多用のダッシュボードUI）
- データ蓄積: 2025-26シーズン（B2昇格）以降

## データソース詳細

### 収集方針

**取れるデータは全て取る。** 技術調査の結果、B.LEAGUE公式・スポナビともにHeadlessブラウザ不要で、curlベースのHTTP リクエストのみでデータ取得が可能であることを確認済み。

### 収集範囲

- **時間軸**: 2025-26シーズン（B2昇格）以降。以降のシーズンも継続蓄積
- **対象**: 横浜エクセレンスが出場した全試合 + B2リーグ全体データ（順位表等）
- **背景**: 2020-21〜2024-25はB3所属のため、B.LEAGUE公式・スポナビともにデータなし

### メインソース: B.LEAGUE公式サイト

横浜エクセレンスの TeamID = `714`

| データ | 取得元ページ | 取得方法 | 備考 |
|--------|------------|---------|------|
| **順位表** | `/standings/?tab=2` | SSR HTMLパース | B2全チームの順位・勝敗・勝率・得失点差・H/A成績・連勝連敗・過去5試合 |
| **試合結果一覧** | `/schedule/?data_format=json&year=2025&event=7&club=714` | JSON API | ページネーション対応（20件/ページ、`index`パラメータ）。スコア・対戦相手・日付・節・会場・ScheduleKey |
| **ボックススコア** | `/game_detail/?ScheduleKey={ID}&tab=2` | HTML内JSオブジェクト（`_contexts_s3id.data`）抽出 | **最重要データ**。全選手の詳細スタッツ: PTS, FGM/A, 3PM/A, FTM/A, RB(OR/DR), AST, TO, ST, BS, FOUL, EFF, +/-, USG, TS%, EFG。クォーター別スコア、スターティング5、観客数、審判名、会場情報も含む |
| **チームスタッツ** | `/club_detail/?TeamID=714` | SSR HTMLパース（テーブル5つ） | シーズン通算/平均: PPG, FG%, 2FG%, 3FG%, FT%, RPG, APG, TOPG, STPG, BSPG, EFFPG。アドバンスドスタッツ: ポゼッション, レーティング, 2NDPTS, FBPS, PITP |
| **選手スタッツランキング** | `/stats/?data_format=json&year=2025&tab=2&target=player-b2` | JSON API | B2全選手ランキング。ポジション・H/A・勝敗・クォーター等のフィルター対応 |
| **選手個人成績** | `/roster_detail/?PlayerID={ID}` | SSR HTMLパース（テーブル4つ） | シーズン通算、試合別成績、アドバンスドスタッツ、プロフィール（ポジション・生年月日・身長/体重・出身地） |
| **全チーム本拠地** | `/club_detail/?TeamID={ID}` | SSR HTMLパース（dt/dd） | ホームタウン、アリーナ名称、住所。B2全14チーム分取得可能 |

#### B.LEAGUE公式 JSON APIパラメータ早見表

**スケジュールAPI** (`/schedule/?data_format=json`):

| パラメータ | 値 | 説明 |
|-----------|-----|------|
| `year` | `2025` | シーズン開始年 |
| `event` | `7` | B2リーグ戦（`8`=B2プレーオフ） |
| `club` | `714` | チームID |
| `fb` | `1`=日程のみ, `2`=結果のみ, 空=全て | |
| `ha` | `1`=HOME, `2`=AWAY | |
| `mon` | `all` or `10`〜`04` | 月指定 |
| `index` | `1`, `21`, `41`... | ページネーション（20件ずつ） |

**選手ランキングAPI** (`/stats/?data_format=json`):

| パラメータ | 値 | 説明 |
|-----------|-----|------|
| `year` | `2025` | シーズン |
| `tab` | `2` | B2 |
| `target` | `player-b2` | B2選手ランキング |
| `value` | `AveragePoints`等 | ソート対象 |
| `dt` | `avg`/`tot`/`dtl` | 平均/合計/詳細 |
| `club` | `714` | クラブフィルタ |
| `p` | `PG`/`SG`/`SF`/`PF`/`C` | ポジションフィルタ |

### ニュース: Google News RSS

```
GET https://news.google.com/rss/search?q=横浜エクセレンス&hl=ja&gl=JP&ceid=JP:ja
```

- 取得可能: タイトル、ソース名、公開日、リンク
- ディスクリプション（記事要約）は取得不可（タイトルの繰り返しのみ）
- 記事数: 約100件

### ニュース: 横浜エクセレンス公式HP RSS

```
GET https://yokohama-ex.jp/RSS.rdf
```

- フォーマット: Atom
- CMS: RCMS（国産CMS）
- 取得可能: タイトル、更新日、リンク、サムネイル画像URL（`enclosure`）
- ディスクリプション（summary/content）は空
- 内容: 試合情報、チケット販売、イベント告知、選手関連ニュースなど公式発表全般
- 用途: Google News RSSとは別に「公式からのお知らせ」として区別表示

### 動画: YouTube公式チャンネル RSS

```

```

- チャンネル: 横浜エクセレンス公式

## データアーキテクチャ

### 基本方針

フロントエンドはDBに蓄積済みのデータを読み取って表示する。ソースサイト（B.LEAGUE・スポナビ）への直接リクエストは、試合中のリアルタイム更新時のみ。

### データフロー

```
[定期バッチ（毎日22:00）]
GitHub Actions
  ├→ B.LEAGUE公式: 試合結果・ボックススコア・選手スタッツ・順位表・チーム成績
  ├→ スポナビ: H2H対戦成績・インジュアリーリスト・チームリーダー
  ├→ Google News RSS / 公式HP RSS: ニュース記事
  ├→ YouTube RSS: 新着動画 → 試合とのマッチング
  └→ AI API: 新しい試合のボックススコアから寸評を生成
      ↓
  DB（JSONファイル → Supabase）に格納
      ↓
  Next.js フロントエンド → DBから読み取って表示

[試合中のリアルタイム（例外フロー）]
Next.js API Route
  └→ B.LEAGUE game_detail を30秒ごとに直接取得
      └→ クライアントに返却（DBには書き込まない）
```

### データ更新タイミング

| データ | 更新タイミング | 更新元 |
| ------ | ------------- | ------ |
| 試合結果・ボックススコア | 毎日22:00バッチ | B.LEAGUE game_detail |
| 選手スタッツ（シーズン平均・通算） | 毎日22:00バッチ | B.LEAGUE roster_detail |
| 選手の試合別成績ログ | 毎日22:00バッチ | ボックススコアから各選手分を抽出 |
| チーム成績・順位表 | 毎日22:00バッチ | B.LEAGUE standings + club_detail |
| H2H対戦成績・インジュアリー | 毎日22:00バッチ | スポナビ widget |
| ニュース（公式HP / Google News） | 毎日22:00バッチ | RSS |
| YouTube動画 | 毎日22:00バッチ | YouTube RSS |
| AI寸評 | 毎日22:00バッチ（新しい試合がある場合のみ） | AI API（生成後DBに保存。再生成しない） |
| **試合中ライブスコア** | **30秒ごとにオンデマンド** | **B.LEAGUE game_detail を直接取得** |

### 備考

- B2の試合は通常18:00〜20:00開始、21:00頃に終了する。22:00バッチなら試合終了後1〜2時間で全データが反映される
- 試合がない日もバッチは実行される（ニュース・YouTube動画の更新があるため）
- リアルタイム取得したデータはDBに書き込まない（22:00バッチで確定データとして格納する）

### P3: 試合詳細ページ `/games/:scheduleKey`

1試合の全情報を集約するページ。ボックススコアが主役。試合中はリアルタイム更新に対応し、試合後にはダイジェスト動画とAI寸評を表示する。

#### リアルタイム更新

試合のステータスに応じて表示モードが自動切替される。

| ステータス | 表示モード | 更新方法 |
| ---------- | ---------- | -------- |
| **試合前** | プレビューモード | 対戦相手情報、チケット購入リンク、試合開始までのカウントダウン |
| **試合中** | ライブモード | 30秒間隔の自動更新（B.LEAGUE game_detailを再取得）+ 画面上部に手動更新ボタン。「LIVE」バッジ表示 |
| **試合後** | 結果モード | 確定データ表示 + ダイジェスト動画 + AI寸評 |

- 試合中の自動更新は `setInterval`（30秒）+ `visibilitychange` イベントで非表示タブ時は停止
- 手動更新ボタン: 最終更新日時を表示し、ボタン押下で即時再取得

## 将来拡張（Phase 2以降）

### Phase 2: データ分析強化

- **選手比較機能**: 2選手のスタッツを並べて比較（レーダーチャートで視覚化）
- **シーズン間比較**: 来シーズン以降、過去シーズンとの成績推移を表示
- **詳細フィルタリング**: 「ホームでの3P成功率」「勝った試合のみのAST」など細かい切り口

### Phase 3: コンテンツ拡充

- **会場データベース**: 全アウェイ会場の情報（所在地・キャパ・アクセス）+ 会場別成績
- **シュートチャート**: B.LEAGUE公式のエリア別シュートデータを可視化（コート図上にヒートマップ）
- **対戦プレビュー**: 次の対戦相手の最近の成績・要注意選手を自動生成
- **ニュースの分類・要約**: Google News RSSのニュースをカテゴリ分類

### Phase 4: ファン向け機能

- **ファン交流**: コメント・SNS連携
- **通知機能**: 試合結果の即時通知（LINE/Discord/メール）
- **お気に入り選手**: 特定選手のスタッツを優先表示
- **ウィジェット/埋め込み**: 他サイトに埋め込めるスタッツウィジェット

### 拡張性を支える技術設計

- **データ層の抽象化**: スクレイピングスクリプトをデータソースごとにモジュール化。新しいソース追加時に既存コードを変更不要
- **DB移行前提の設計**: MVPではJSONファイル、Phase 2以降でSupabase（PostgreSQL）に移行。データアクセス層をRepository パターンで抽象化し、移行時のフロントエンド変更をゼロにする
- **APIルート設計**: Next.js API Routesでデータ提供。将来的に外部公開APIとしても使える構造
- **コンポーネント設計**: チャートコンポーネントは汎用化し、異なるページで同じグラフを再利用可能にする

## 実現可能性

### 技術的実現可能性: 容易

技術調査の結果、B.LEAGUE公式・スポナビともに**Headlessブラウザ不要**。curlベースのHTTPリクエストのみでデータ取得可能であることを確認済み。B.LEAGUE公式はJSON APIも提供しており、スクレイピングの実装難易度は低い。フロントエンドはNext.js（メインスキル）で問題なく対応可能。

### コスト: 低コスト

- ホスティング: Vercel無料枠
- DB: JSONファイル（MVP）→ Supabase無料枠（Phase 2〜）
- ドメイン: 独自ドメイン取得で年額1,000〜2,000円程度（任意）
- スクレイピング実行環境: GitHub Actions無料枠
- ニュース: Google News RSS + 公式HP RSS（無料）
- 動画: YouTube RSS（無料）
- AI寸評: Claude API or OpenAI API（従量課金。1試合あたり数円。月30試合想定で月額100〜300円程度）

### 差別化: 高い

競合調査の結果、**横浜エクセレンスに特化したスタッツダッシュボードは存在しない**。既存のBリーグスタッツサイトはリーグ全体をカバーしており、特定チームにフォーカスしたダッシュボードは皆無。「B2の特定チームに特化」というニッチは完全に空白領域。

### 需要（Dogfooding）: 高い

自分自身が横浜エクセレンスのファンであり、複数サイトを行き来して情報を集めている現状を解消したいという強い動機がある。

### 工数: 中〜大（目安: 2〜3週間）

- スクレイピング基盤: 3〜4日（技術調査完了済みのため短縮）
- フロントエンド MVP（8ページ）: 7〜10日
- リアルタイム更新 + YouTube連携 + AI寸評: 2〜3日
- テスト・調整: 2〜3日

## リスクと懸念事項

- **サイト構造変更によるスクレイピング破損**: シーズン切り替えやリニューアルでスクレイピングが壊れるリスク。**対策**: データ取得部分をモジュール化し、変更時に最小限の修正で対応。GitHub Actionsのエラー通知設定
- **利用規約への抵触**: B.LEAGUE公式・スポナビのスクレイピングがグレーゾーン。**対策**: 非商用・個人利用を明示、適切なリクエスト頻度（1秒以上の間隔）、データ出典を必ず記載
- **スポナビWidget URLの変更**: widget URLパターンが予告なく変更される可能性。**対策**: サブソースなのでメインに影響なし。壊れた場合はB.LEAGUE公式のみで運用可能な設計にする

### デザインパターン

- **ライト基調**: 白背景 + チームカラーのグリーンをアクセントに使用
- **ダッシュボードUI**: グラフ・チャートを多用し、データを視覚的に訴求
- **カード + グリッドレイアウト**: 情報をカード単位で整理し、一覧性を確保
- **タイポグラフィ**: 数字やスコアを大きく太く印象的に表示。画像に頼らずデータとフォントで魅せるデザイン
- **一貫した配色ルール**: 勝ち=グリーン、負け=グレー、自チーム=グリーン、相手チーム=グレー

### 使用するグラフ種別

| グラフ | 用途 | ページ |
|--------|------|--------|
| 折れ線グラフ | 得点推移、スタッツ推移 | トップ、選手詳細 |
| 棒グラフ（グループ） | Q別得点比較、月別成績 | 試合詳細、チーム成績 |
| 水平バーチャート | チーム比較、シューティングスプリット | 試合詳細、選手詳細 |

## 技術スタック（案）

| レイヤー | 技術 | 選定理由 |
|----------|------|----------|
| フロントエンド | Next.js (App Router) | メインスキル。SSG/ISRでパフォーマンスも確保 |
| スタイリング | Tailwind CSS | ユーティリティファーストで効率的に開発 |
| データ可視化 | Recharts | React対応。軽量でカスタマイズ性が高い。9種類のグラフに対応 |
| データ取得 | Python (HTTP + HTMLパース) | knowledge-hubで経験済み。Headlessブラウザ不要 |
| DB | JSONファイル → Supabase | MVPではJSON、Phase 2でSupabase移行。Repository パターンで抽象化 |
| ホスティング | Vercel | Next.jsとの相性最良。無料枠で運用可能 |
| バッチ実行 | GitHub Actions | 定期実行の自動化。無料枠で十分 |
| ニュース | Google News RSS + 公式HP RSS | 無料。メディア記事 + 公式お知らせの2ソース体制 |
| 動画 | YouTube Data API (RSS) | 無料。公式チャンネルからダイジェスト動画を自動取得・マッチング |
| AI寸評 | Claude API or OpenAI API | ボックススコアデータを入力し試合寸評を自動生成。API利用料は従量課金（1試合あたり数円程度） |

## ネクストアクション
