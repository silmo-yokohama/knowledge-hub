# レシピ管理AIアレンジアプリ

> カテゴリ: 趣味・プライベート
> 作成日: 2026-07-07
> ステータス: アイデア段階

---

## 概要

料理レシピを構造化データとして蓄積し、Claude Codeで自分・パートナーの好みに合わせてAIアレンジし、栄養価まで評価した上でスマホで見やすく・調理しやすく管理するアプリ。既存アプリ「CookGo」の「材料と手順が同期しない」「お気に入り・検索が弱い」という不満を解消しつつ、従量課金のAIを使わず契約済みの Claude MAX(x5) の定額内で完結させる。

---

## 5W1H

### What（何を）

- 料理レシピを **材料=変数、手順={{token}}参照** の形で構造化データ（YAML）として `recipes/` に蓄積するリポジトリ
- Claude Code を使い、好みプロファイル・過去レシピ・公的な栄養データベースを参照しながらレシピをAIアレンジ・評価
- Astro製PWAビューアで一覧・検索・タグ絞り込み・人前スケーリング・調理モード表示
- Supabase で日常的な操作（お気に入り・週間予定表・買い物リスト）を管理

### Why（なぜ）

- CookGoの2つの不満を解消したい：①人前を変更すると材料は更新されるが手順の文章は同期されないまま、②お気に入り登録ができず検索も使いにくい
- 従量課金のAI APIは使いたくないが、既に契約済みの Claude MAX(x5) の定額内でYouTube/Instagram等のレシピを自分好みにアレンジしたい
- 使うほど好みを学習し、栄養バランスまで評価してくれる、CookGoにはない「使うほど育つ」レシピ管理を実現したい

### Who（誰が）

- **メインユーザー**：清水陽平（料理担当、iPhone）
- **サブユーザー**：同棲中のパートナー（Android）。閲覧・お気に入り中心の軽い利用を想定

### When（いつ）

未定（個人の空き時間で進行。副業ではなく趣味・生活改善が目的）

### Where（どこで）

- **オーサリング**：Claude Code（スマホブラウザの claude.ai/code、または普段使いの Antigravity 環境）
- **閲覧**：Astro製PWA（GitHub Pages等でホスティング、スマホブラウザ）
- 清水: iPhone / パートナー: Android

### How（どうやって）

4つの入口（① CookGo取り込み→PDF共有、② レシピサイト/YouTube URL、③ テキスト貼り付け、④ ゼロベースの相談）からレシピの元情報を取得し、Claude Codeが好みプロファイル・過去レシピ・食品成分データベースを参照しながらアレンジと栄養評価を行う。確定したレシピはYAMLとしてgit commitでリポジトリに保存し、Astro製ビューアが読み込んで表示する。お気に入り・週間予定表など日常的にアプリから読み書きする部分はSupabaseで管理する。

## 実現可能性

### 技術的実現可能性: 可能

Astro/フロントエンドは既存スキル（WordPress副業アイデア等）の延長で対応できる。Claude Codeでのリポジトリ運用、栄養計算式の実装、Supabase連携は新規要素だが、公的データ（文部科学省 日本食品標準成分表）や既存のMCP接続（Supabase）を活用できるため学習コストは限定的。

### コスト: 無料

Claude MAX(x5)の定額、GitHubリポジトリ+Pagesの無料枠、Supabase無料枠（500MB DB。日常利用なら十分）で完結する。従量課金のAI APIは使用しない。

### 差別化: 高い

CookGo・クラシル・Cookpad等の既存レシピアプリは「取り込んで保存」「レシピを探す」までで止まっている。本アプリは以下の点で明確に差別化できる：

- 材料と手順が同一データを参照するため、人前を変更しても**手順の記述とズレない**（CookGoは分量変更時に「酒 5/8大さじ」のような非実用的な数値をそのまま表示するが、本アプリは実用値に丸めて表示できる）
- 公的データ（食品成分表2020年版八訂）に基づく栄養評価と、既存レシピを検索した上での栄養バランス改善提案
- 好みプロファイルを蓄積し、**使うほど提案の精度が上がるフライホイール**がある

### 需要（Dogfooding）: 高い

CookGoの実使用で日常的に感じている具体的な不満の解消が起点であり、毎日の料理で使うことがほぼ確実。

### 工数: 大（目安: Step0〜Step3で数週間〜1ヶ月程度、空き時間ベース）

Step0（データ基盤）→Step1（オーサリング検証）→Step2（ビューアMVP）→Step3（調理モード）の4段階構成。詳細は下記ネクストアクション・別紙のロードマップを参照。

## リスクと懸念事項

- **CookGoのPDFエクスポートが画像ベースであるため、Claude Code単体では文字として読み取れない**（`pdftoppm`等の画像変換ツールがサンドボックスに無い場合が多い）。対策：当面はチャットのClaudeアプリでPDFをOCR/YAML化し、その結果をClaude Codeに渡してコミットする2アプリ併用とする。手間が増えた場合のみ、PDF→画像変換スクリプトをリポジトリに常備してClaude Code単独に寄せる
- **栄養価・健康効果の記述に、医学的根拠のない俗説（都市伝説）を書いてしまうリスク**（例：特定の食品添加物への根拠なき非難）。対策：`benefits`/`cautions` は「計算した栄養素の値」と「公的な基準値（食事摂取基準等）との比較」からのみ記述可能というルールを明文化し、それ以外の言説は禁止する
- **レシピ本体はgit、日常操作はSupabaseという二重構成により、データ設計と同期の複雑さが増す可能性**。対策：「Claude Codeのみが参照・更新するもの＝リポジトリ」「アプリからも参照・更新するもの＝DB」という単純なルールで一貫して切り分ける
- **個人開発のため、実際に使ってみないと本当に必要な機能の形が確定しない**（特に買い物リスト・週間予定表まわり）。対策：v1はレシピの登録・閲覧・調理モードという最小の3ステップに絞り、お気に入り・週間予定表・買い物リスト等のDB系機能はv1運用後のv2に回す

## MVP 定義

### スコープ（v1）

- [ ] リポジトリ構成・YAMLスキーマ・好みプロファイルの型を確定する（Step0）
- [ ] 4つの入口（CookGo/URL/テキスト/ゼロベース）から、Claude Codeで実際にレシピを変換・保存できる（Step1）
- [ ] Astro製PWAビューア：一覧・詳細・人前スケーリング・検索・dish/tags絞り込み（Step2）
- [ ] 調理モード：手順を1ステップずつ大きく表示する画面（Step3）

**v1リリースの定義**：4つの入口すべてから迷わずレシピを保存でき、あなた・パートナーそれぞれのスマホでアプリを開けば検索・タグ絞り込み・人前変更・調理モードが問題なく動き、実際に2週間の日常の料理で使ってみて致命的な不便がない状態。

### スコープ外（将来対応 v2以降）

- お気に入り機能（Supabase、ビューアから直接操作。二人で共有）
- 週間予定表（Supabase、基本はアプリ上で組む。例外的にClaude Codeからも追加可能）
- 買い物リストの自動生成（週間予定表に載ったレシピの材料をビューアがその場で集計。在庫管理は行わない）
- 好みプロファイルの自動学習、モード切替（時短・節約・使い切り・ヘルシー）
- 調理履歴の記録、冷蔵庫写真からの献立提案
- パートナーも編集可能にする、レシピの外部公開・ブログ化（`04.BlogDrafts` との連携の可能性はあるが今回は保留）

## 技術スタック（案）

| レイヤー | 技術 | 選定理由 |
|----------|------|----------|
| オーサリング | Claude Code（CLI / Web / Antigravity） | リポジトリのネイティブ操作（Read/Write/Grep/git commit）がそのまま使え、命名の一貫性運用（既存レシピをGrepして再利用）も担える |
| データ（レシピ・好みプロファイル） | Git リポジトリ + YAML | Claude Codeの得意領域。無料でバージョン履歴が付く。`01.Research` と同じ設計思想 |
| データ（対話的な状態） | Supabase | お気に入り・週間予定表・買い物リストのチェック等、アプリから直接読み書きが必要な部分を担当。無料枠で十分 |
| フロントエンド/ビューア | Astro（静的サイト＋一部クライアントフェッチ） | `01.Research/viewer` と同じ構成を流用。タグ/カテゴリ絞り込みの実装パターンも流用可能 |
| ホスティング | GitHub Pages | 既存の `.github/workflows/deploy.yml` の仕組みを流用可能 |
| 栄養計算 | 日本食品標準成分表2020年版（八訂） | 公的根拠に基づく固定の計算方式。Claude Codeが都度算出し、CookGo等の値には依存しない |

## ネクストアクション

1. レシピ・好みプロファイル用のディレクトリ構成（`recipes/`, `profiles/silmo.md`, `profiles/partner.md`）を用意し、YAMLスキーマ定義書（材料=変数+id、手順={{id}}参照、`nutrition`/`cautions`/`benefits`/`balance`/`dish`/`tags` の構造と生成ルール）を作成する
2. 実際に「マルタイで作る冷やし中華」（CookGoから取得済みの実例）を手動でこのスキーマに変換し、破綻がないか検証する
3. 4つの入口それぞれから最低1件ずつ、実際に使うレシピをClaude Codeで登録してみる（Step1の検証）
