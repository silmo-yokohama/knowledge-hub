> ステータス: アイデア段階

---

## 概要

横浜エクセレンス（B.LEAGUE B2）に特化したファンサイト。B.LEAGUE公式やYahoo Sportsから試合結果・選手スタッツを自動収集し、データビジュアライゼーションで見やすく整理する。加えて、自分が観戦した試合の観戦記を手動で投稿する。「バスケを深く知れる場所」をコンセプトに、公式サイトでは得られない情報体験を提供する。

---

## 5W1H

### What（何を）

横浜エクセレンスの試合結果・選手スタッツ・順位を自動集計して見やすく表示するWebサイト。観戦記（手書きのブログ記事）も掲載する。

### Why（なぜ）

- B.LEAGUE公式サイトは情報が散らばっていて見づらい
- エクセレンス公式サイトは販促情報が中心で、「バスケの中身」を深く知ることができない
- 横浜エクセレンスはまだ知名度が低い発展途上のチームであり、ファン目線で情報を発信することでチームの認知向上に貢献したい

### Who（誰が）

- メインユーザー: 自分自身（Dogfooding）
- 想定ユーザー: 横浜エクセレンスの既存ファン、Bリーグに興味がある人、横浜エクセレンスをこれから知る人

### When（いつ）

- 未定（B.LEAGUEシーズン中のリリースが理想）

### Where（どこで）

- Webサイト（レスポンシブ対応、PC/スマホ両対応）

### How（どうやって）

- データ取得: B.LEAGUE公式サイト・Yahoo SportsからHTMLスクレイピング（Python バッチ処理で自動化）
- フロントエンド: Next.js（得意技術を活かす）
- データ可視化: Chart.js / Recharts 等のライブラリ
- 観戦記: Markdown or CMS で手動投稿

---

## 実現可能性

### 技術的実現可能性: 可能

フロントエンドはNext.js（メインスキル）で問題なく対応できる。データ取得のスクレイピングはPython（学習中）だが、knowledge-hubプロジェクトで経験済み。データビジュアライゼーションはChart.js/Recharts等のライブラリで実現可能。

### コスト: 無料〜低コスト

- ホスティング: Vercel無料枠
- DB: Supabase無料枠 or JSONファイル（MVP段階）
- ドメイン: 独自ドメイン取得で年額1,000〜2,000円程度（任意）
- スクレイピング実行環境: GitHub Actions無料枠 or ローカルcron

### 差別化: 高い

横浜エクセレンスに特化したファンサイトは現時点で存在しない。B.LEAGUEのスタッツサイト（B.League Analytics、bleague-stats.com等）はリーグ全体をカバーしているが、特定チームに深く寄り添ったサイトは見当たらない。スタッツ（データ）と観戦記（読み物）の組み合わせも差別化ポイント。

### 需要（Dogfooding）: 高い

自分自身が横浜エクセレンスのファンであり、試合結果や選手スタッツを見やすくまとめたいという強い動機がある。現状、複数のサイトを行き来して情報を集めている状態を解消できる。

### 工数: 中（目安: 1〜2週間）

- スクレイピング基盤: 2〜3日（knowledge-hubのスクリプト経験を活用）
- フロントエンド（MVP）: 4〜5日
- 観戦記機能: 1〜2日
- テスト・調整: 1〜2日

## リスクと懸念事項

- **スクレイピング対象のサイト構造変更**: シーズン切り替えやリニューアルで壊れるリスクがある。対策として、スクレイピング部分をモジュール化し、変更時に最小限の修正で対応できる構造にする
- **利用規約への抵触**: B.LEAGUE公式・Yahoo Sportsのスクレイピングがグレーゾーン。対策として、非商用・個人利用であることを明示し、適切なリクエスト頻度を守る。データの出典を必ず記載する
- **運用の継続性**: 個人開発ゆえ、モチベーション低下で放置されるリスク。対策として、データ更新はバッチ自動化で手間を最小化し、手動は観戦記のみに限定する

## MVP 定義

### スコープ

- [ ] 試合結果一覧ページ（スコア・日付・対戦相手）
- [ ] 選手一覧ページ（背番号・名前・ポジション・主要スタッツ）
- [ ] チーム順位表示
- [ ] データ取得バッチ（B.LEAGUE公式からのスクレイピング）
- [ ] 観戦記投稿・表示機能（Markdownベース）

### スコープ外（将来対応）

- 試合ごとの詳細ボックススコア
- 選手スタッツのグラフ・チャート表示
- シーズン間の成績比較
- ニュース集約（Yahoo Sports等）
- SNS連携
- コメント・ファン交流機能

## デザイン方針

### カラーパレット

| 役割 | カラー | コード |
|------|--------|--------|
| プライマリ | ダークグリーン | `#006d3b` |
| プライマリ（ホバー） | 濃いグリーン | `#005a31` |

### デザインパターン

- **ライト基調**: 白背景 + チームカラーのグリーンをアクセントに使用
- **データビジュアライゼーション重視**: チャート・スコアボード風UI・プログレスバーでスタッツを可視化
- **カード + グリッドレイアウト**: 試合カード・選手カードで情報を整理し一覧性を確保
- **タイポグラフィ**: 数字やスコアを大きく印象的に表示。画像に頼らずデータとフォントで魅せるデザイン

## 技術スタック（案）

| レイヤー | 技術 | 選定理由 |
|----------|------|----------|
| フロントエンド | Next.js (App Router) | メインスキル。SSG/ISRでパフォーマンスも確保 |
| スタイリング | Tailwind CSS | ユーティリティファーストで効率的に開発 |
| データ可視化 | Recharts or Chart.js | React対応のチャートライブラリ |
| データ取得 | Python (スクレイピング) | knowledge-hubで経験済み。バッチ処理向き |
| DB | Supabase or JSON | MVPではJSONファイル、拡張時にSupabase移行 |
| ホスティング | Vercel | Next.jsとの相性最良。無料枠で運用可能 |
| バッチ実行 | GitHub Actions | 定期実行の自動化。無料枠で十分 |

## ネクストアクション

1. B.LEAGUE公式サイトのHTML構造を調査し、スクレイピング可能なデータ項目を洗い出す

3. スクレイピングスクリプトのプロトタイプを作成し、データ取得の実現可能性を検証する
