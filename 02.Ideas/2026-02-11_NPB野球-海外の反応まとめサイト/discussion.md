# 壁打ち記録: BatFlip（バットフリップ） - NPB野球 海外の反応メディア

> 実施日: 2026-02-11
> 参加者: 清水陽平 / Claude

---

## 対話ログ

### ラウンド1: アイデアの方向性探し

**清水**: 運用コストがかからず、メンテナンスコストも低く、アクセスが稼げて広告収入でマネタイズできるサービスを作りたい。まだ具体的な内容は決まっていない。

**Claude**: 3つの方向性を提示。
1. ニッチ特化アンテナサイト（特定ジャンル）
2. プログラマティックSEO型（データからページ大量生成）
3. ツール型サイト（便利系）

**清水**: ツール系は飽きられるので情報で勝負したい。アンテナサイトなら野球関連に特化する想定。既存の野球アンテナサイトは広告が多すぎるので、適度な広告量で差別化できる。プラスで付加価値も欲しい。

---

### ラウンド2: 付加価値の模索とRedditの発見

**Claude**: 「広告が少ない」だけでは差別化として弱い（真似しやすく、参入障壁にならない）と指摘。清水さんのスキルセット（フロントエンド + AI/LLM + RSS/コメント取得スクリプト資産）を活かした付加価値として、AI要約・ファン反応ヒートマップ・試合データ連動・チーム別フィルタを提案。

**清水**: 「RedditにNPBの話題はあるか？ あれば翻訳・要約してLLMで独自記事を自動作成できるかも」と発案。X（Twitter）はAPI制約と個人的な理由で除外。

**Claude**: r/NPBを調査し、購読者47,000人の活発なコミュニティを確認。「海外の反応」は日本で実績のあるジャンルで、NPB特化は空白地帯。LLMとの相性も良く、筋の良い方向性と評価。

---

### ラウンド3: コンテンツ・機能の具体化

**清水**: コンテンツの詳細を整理。
- Reddit記事: 翻訳＋コメントキュレーション（2chまとめ風に面白い・皮肉・議論コメントを選別）
- 国内ニュース: AI要約＋Yahooニュースコメントの議論ポイント
- 収集対象: NPB、WBC/オリンピック等の国際大会、MLBの日本人選手
- 機能: カテゴリ分け、タグ、検索、コメント機能（UX重視）
- 自動収集＆翻訳＆投稿のパイプライン

**Claude**: 3つのフィードバック。
1. **コメント機能はメンテナンスコストの爆弾**になりうる（スパム・荒らし対策、法的責任、モデレーション負荷）。MVP段階では外すべき
2. 記事生成の**頻度とワークフロー**を決める必要がある
3. **技術スタック**: Next.js + microCMS が最適。WordPressヘッドレスはメンテ負荷で不向き

---

### ラウンド4: 運用・技術の詰め

**清水**:
- コメント機能はゆくゆくでOKだが優先度は高い。通報システム＋一定数で非表示の自治型を考えたい
- 記事生成は可能であれば定時実行。人間の作業は最小限に
- デイリー試合結果レポート（23時頃）も追加したい。活躍した選手、出来事、順位変動グラフ含む
- 技術スタックはNext.js + microCMSで考えている。将来のコメント機能を考慮するとDB（Turso? Supabase?）も必要では

**Claude**:
- Turso vs Supabaseを比較し、**Supabaseを推奨**（認証機能組み込み済み、RLS、リアルタイム対応）
- X API Free tierで月500投稿可能。宣伝用途なら十分
- 順位変動グラフはmicroCMSにJSON格納 → フロントでChart.jsレンダリングが最適

**清水**: グラフは画像ではなくJSONデータ + Chart.jsでのレンダリングを希望。

---

### ラウンド5: LLMモデルと実行環境

**清水**: LLMはローカル運用（自分のPCでClaude CodeのSkill/Commandsを実行する形）を想定していた。APIではなくMAXプラン内で運用したい。モデルは精度重視でSonnet 4.5以上、できればOpus 4.6を希望。また、不要なMacBookがあるので、それを常時稼働サーバーとして使える。

**Claude**: MAXプラン内運用なら追加コスト$0。翻訳・キュレーションのタスクにはSonnet 4.5がベストバランス（Opusは推論向きでこの用途にはオーバースペック気味）。ただしMAXプランならコスト差がゼロなのでOpus使用も合理的。余剰MacBookをcrontab + Claude Codeの定時実行環境にするのが最もクリーンな解決策と評価。EC2の規約リスク・コストが全て解消される。

## 議論のまとめ

### アイデアの変遷

1. **初期**: 「低コスト・低メンテでアクセスが稼げて広告収入を得られるサービス」（白紙状態）
2. **方向性決定**: 野球特化のアンテナサイト。広告控えめのUXで差別化
3. **差別化強化**: Reddit r/NPBの海外ファンのコメントを翻訳・キュレーションする「海外の反応」要素を追加
4. **最終形**: 3本柱のコンテンツ（Reddit翻訳記事 + 国内ニュース要約 + デイリー試合結果）をAIで自動生成する野球メディア

### 主要な論点

- **差別化の核心**: 「広告が少ない」だけでは弱い → NPB特化の海外の反応コンテンツが真の差別化要因
- **コメント機能**: メンテナンスコストの懸念 → MVPでは見送り、優先度は高く保持。通報＋自治システムで将来実装
- **技術スタック**: WordPress vs Next.js + microCMS → メンテナンスコスト重視でNext.js + microCMSに決定。DBはSupabase（コメント追加時）
- **自動化レベル**: 完全自動 vs 半自動 → 余剰MacBook + crontab + Claude Code（MAXプラン）で定時実行
- **LLMモデル選定**: Haiku vs Sonnet vs Opus → Sonnet 4.5がベストバランス。MAXプラン内ならOpus 4.6も選択可
- **グラフ表現**: 画像生成 vs JSONデータ + クライアントサイドレンダリング → 後者を採用（インタラクティブ、実装がシンプル）

### 出たフィードバック

#### 肯定的な評価

- 「海外の反応」は日本で実績のあるジャンル。NPB特化は空白地帯
- LLMの翻訳・要約・キュレーション能力との相性が抜群
- 運営者自身がNPBファン（Dogfoodingの観点で高評価）
- 3つのコンテンツ柱（Reddit / 国内ニュース / 試合結果）で安定したコンテンツ供給が可能
- MLBの日本人選手を対象に含めたことでコンテンツ量を確保

#### 指摘事項と対応

| 指摘内容 | 対応方針 |
|----------|----------|
| コメント機能はメンテナンスコストの爆弾 | MVPでは見送り。Supabase + 通報/自治システムで将来実装 |
| 「広告が少ない」だけでは差別化にならない | 海外の反応コンテンツ + AI要約で独自性を確保 |
| AI生成コンテンツはSEOで不利になる可能性 | キュレーション（コメント選別・構成）で独自性を出す |
| r/NPB単体ではコンテンツ量が不足する可能性 | 国内ニュース + 試合結果でカバー。r/baseballのNPB関連も収集対象 |
| Redditコンテンツの著作権グレーゾーン | 元投稿リンク必須、引用範囲内、DMCA対応ポリシー |
| EC2でのClaude Code運用は規約リスクあり | 余剰MacBookを常時稼働サーバーに。自分の端末なので規約問題なし |
| LLM APIコストの懸念 | MAXプラン内運用で追加コスト$0に解決 |

### 未解決の課題

- サイト名・ドメイン名が未定
- 試合結果データの具体的な取得元（NPB公式? スポーツナビ? API?）
- LLMのコメント選別精度の検証（プロトタイプで確認が必要）
- Google AdSenseの審査通過に必要な初期コンテンツ量の見積もり
- microCMS無料枠の制限（API 3つ、コンテンツ10,000件）で足りるかの検証
